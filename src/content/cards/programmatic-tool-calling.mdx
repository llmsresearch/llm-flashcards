Programmatic tool calling lets model-written code coordinate tool calls inside an execution environment. The code can loop over records, combine results and filter them before returning a summary to the model.

## Keep intermediate records in the execution environment

In a conventional loop, each tool result enters the conversation and the model chooses the next action. With programmatic coordination, several calls and intermediate calculations can happen within one code execution. The model receives the selected output instead of every raw record.

The card shows tool records being reduced to two counts, A: 4 and C: 1. That small result is enough for the next response; the raw records stay in the execution environment. This can reduce context usage when most returned data is only needed for filtering or aggregation.

## Execution still needs boundaries

The runtime determines which tools are callable and enforces their permissions. Generated code is not a reason to grant broader access. Timeouts, partial failures and unintended side effects still need handling, especially when a loop calls a tool many times. Return enough evidence to explain the result without dumping all intermediate data into context.
